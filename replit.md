# HutaoTik

A dark-themed TikTok / YouTube / Facebook video downloader with an admin dashboard and notification system.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080, served at `/api`)
- `pnpm --filter @workspace/hutaotik run dev` — run the frontend (Vite dev server)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string (auto-provisioned)
- Optional env: `ADMIN_PASSWORD` — admin login password (default: `lablabnakohutao`)

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- Frontend: React + Vite + Tailwind CSS v4 + Wouter routing + TanStack Query
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)
- Video fetching: tikwm.com API (TikTok), yt-dlp binary (YouTube/Facebook)

## Where things live

- `lib/api-spec/openapi.yaml` — source-of-truth API contract
- `lib/db/src/schema/` — 6 Drizzle schema files (announcements, admin_settings, monitored_accounts, post_notifications, download_history, showcase_videos)
- `artifacts/api-server/src/routes/` — all Express route handlers (tiktok, youtube, facebook, admin, announcements, notifications, downloads, showcase, etc.)
- `artifacts/api-server/src/lib/` — server libs: tikwm.ts, youtube.ts, facebook.ts, monitor.ts, cache-image.ts, recache-thumbnails.ts, logger.ts, cobalt.ts
- `artifacts/hutaotik/src/pages/` — Home, History, Notifications, Admin, Showcase, NotFound
- `artifacts/hutaotik/src/components/` — Layout, YouTubeSection, FacebookSection, plus shadcn/ui components
- `yt-dlp` — yt-dlp binary in workspace root, used for YouTube/Facebook downloads
- `attached_assets/` — logo and banner fallback images (referenced via `@assets/` alias in Vite)

## Architecture decisions

- Admin auth uses a hardcoded token string `hutaotik-admin-token` passed as `x-admin-token` header; token is stored in `localStorage` and applied globally via `setExtraHeaders()`.
- The TikTok monitor polls every 60s using tikwm.com to detect new videos from monitored accounts and stores notifications in the DB.
- YouTube/Facebook downloads invoke `yt-dlp` as a subprocess via `spawn`.
- The app is entirely dark-mode — CSS vars are set once on `:root`, no `.dark` class toggle needed.
- `setExtraHeaders` / `clearExtraHeaders` are custom additions to `lib/api-client-react/src/custom-fetch.ts` (not generated by Orval) — they let the admin page inject the `x-admin-token` header globally.

## Product

- Paste any TikTok, YouTube, or Facebook URL → get download links (HD, normal, audio, photos)
- Bulk-download TikTok photo posts as a ZIP via JSZip
- Showcase page: curated videos from monitored accounts
- Notification bell: alerts for new posts from monitored TikTok accounts
- History page: recent downloads
- Admin dashboard (6 tabs): Branding, Social links, Announcements, Monitored accounts, Showcase management, Feature toggles

## Gotchas

- `yt-dlp` binary lives at the workspace root (`/home/runner/workspace/yt-dlp`). Routes call it via `spawn` with the full path.
- After any OpenAPI spec change, always re-run codegen before touching route or frontend code.
- `pnpm run typecheck:libs` must be run after editing any file in `lib/api-client-react/src/` — the lib needs to be rebuilt so Vite/TS picks up changes.
- The hutaotik frontend uses `@assets/` Vite alias pointing to `attached_assets/` for logo/banner fallback images.
